# Repository map

Where things are, what is hand-written, and what is generated. Verified against the tree at commit `f96b6bb`.

## Top level

```
Robot-Charge-Controller-HMI/
├── README.md              Project front page (preview images, quick start)
├── assets/ui/             README preview PNGs (captures of the mockup)
├── docs/                  This documentation
│   └── mockups/           Browser replica of the UI (reference only)
├── firmware/              ESP-IDF project: the code that runs on the device
├── lvgl_ui/               LVGL Pro Editor project: layouts (XML) and their generated C
└── tools/snapshot/        README preview export and a PC renderer of the UI components
```

Two things to keep apart:

- **`firmware/`** is the buildable product. It owns the logic, drivers, services and pages.
- **`lvgl_ui/`** owns the *look* of the screens. The firmware compiles part of its generated C (see below).

## `firmware/`

```
firmware/
├── CMakeLists.txt          project; EXTRA_COMPONENT_DIRS lists the five layer directories
├── sdkconfig.defaults      tracked configuration (sdkconfig itself is generated, gitignored)
├── partitions.csv          dual OTA app slots
├── dependencies.lock       pinned managed components (lvgl, esp_lvgl_port, esp_lcd_st77922...)
├── main/                   main.c -> app_run() in app.c: composition root
├── components/
│   ├── common/hmi_common         rcc_snapshot_t, board constants (hmi_config.h)
│   ├── bsp/bsp_elecrow_s3        ST77922 LCD + LVGL port, touch, LEDC backlight
│   ├── protocol/rcc_codec        frame codec (pure C)
│   ├── protocol/rcc_link         UART1 task, snapshot, START/STOP
│   ├── services/hmi_settings     NVS settings
│   ├── services/hmi_wifi         Wi-Fi station, posts events
│   ├── services/hmi_ota          Web OTA server, rollback confirmation
│   ├── services/hmi_power        brightness, dim/sleep
│   └── ui/ui_assets | ui_present | ui_core | ui_app
├── test/host/              C host tests + Python controller_sim tests
├── tools/                  controller_sim.py, gen_icons.py, sim/ (desktop UI simulator)
└── .devcontainer/          ESP-IDF dev container pinned to v6.1
```

Generated or local, **not** tracked: `build/`, `sdkconfig`, `sdkconfig.old`, `managed_components/`, `tools/sim/out/`.

Layer rules and recipes: [`firmware/components/README.md`](../../firmware/components/README.md). UI internals: [`firmware/components/ui/README.md`](../../firmware/components/ui/README.md).

## `lvgl_ui/` (LVGL Pro project)

```
lvgl_ui/
├── project.xml             480 x 320 target, LVGL 9.6.0
├── components/hmi/rcc_*/   LAYOUT COMPONENTS: <name>.xml + <name>_gen.c/.h   <- compiled into firmware
├── screens/hmi_*.xml       PREVIEW SCREENS with sample data (+ _gen.c/.h)     <- not compiled into firmware
├── fonts/hmi/              Montserrat TTFs used by the layouts
├── images/hmi/             icon PNGs
├── globals.xml, translations.xml
├── lvgl_ui.c/.h, lvgl_ui_gen.c/.h, file_list_gen.cmake, CMakeLists.txt   Editor-generated aggregate (not used by firmware)
├── sim/                    Editor's built-in desktop simulator (SDL2 / Win32)
├── HMI.md, README.md       short pointers to docs/05-ui/lvgl-pro-workflow.md
└── preview-build/, preview-bin/, build/, .cache.json   Editor output, gitignored
```

How the firmware consumes it: `firmware/components/ui/ui_app/CMakeLists.txt` globs `lvgl_ui/components/hmi/*/*_gen.c` and adds each directory to the include path. Nothing else under `lvgl_ui/` is compiled into the device image. Details: [lvgl-pro-workflow.md](../05-ui/lvgl-pro-workflow.md).

## `tools/snapshot/`

A CMake project that builds the UI components with LVGL on a PC and renders 480 × 320 bitmaps, plus Python scripts that export the README previews (`export_previews.py`, `export_mockup_previews.py`). It needs LVGL from `firmware/managed_components/`, so build the firmware once first.

## Hand-written vs generated

| Path | Origin | Edit by hand? |
|---|---|---|
| `firmware/main/`, `firmware/components/**/src`, `**/include` | hand-written | yes |
| `firmware/components/ui/ui_assets/src/` (icons, fonts) | generated by `firmware/tools/gen_icons.py` and the font README | regenerate, do not hand-edit |
| `lvgl_ui/**/*_gen.c`, `*_gen.h` | generated by LVGL Pro (Ctrl+B) | **no**; edit the `.xml` in the Editor |
| `lvgl_ui/**/*.xml` | authored in the Editor | via the Editor (or XML, carefully) |
| `firmware/sdkconfig.defaults`, `partitions.csv`, `dependencies.lock` | hand-maintained / tool-maintained | yes (lock file via the component manager) |
| `firmware/sdkconfig`, `build/`, `managed_components/` | build output | no; gitignored |
| `assets/ui/*.png` | exported from the mockup | regenerate with `tools/snapshot` |
| `docs/mockups/hmi-ui-landscape.html` | hand-written reference | yes, but the firmware is authoritative |

## Where do I change X?

| Change | Start here |
|---|---|
| How a region looks (size, colour, position) | `lvgl_ui/components/hmi/rcc_*` in the Editor, then Ctrl+B |
| What text/tone a value shows | `firmware/components/ui/ui_present/` (+ `test/host/test_hmi_present.c`) |
| Which widget gets which value | `firmware/components/ui/ui_app/src/pages/page_*.c` |
| A new controller field | The six-step table in `firmware/components/README.md` |
| Controller protocol decoding | `firmware/components/protocol/rcc_codec` |
| UART pins or timeouts | `firmware/components/common/hmi_common/include/hmi_config.h` |
| Display/touch pins | `firmware/components/bsp/bsp_elecrow_s3/src/bsp_pins.h` |
| Start-up order or wiring between modules | `firmware/main/app.c` |
| Partition layout, PSRAM, LVGL memory | `firmware/sdkconfig.defaults`, `firmware/partitions.csv` |
